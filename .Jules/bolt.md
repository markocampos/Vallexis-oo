## 2024-05-24 - Database Optimization

**Learning:** Missing database indexes on heavily queried columns like `claims.is_fulfilled`, `payment_notifications.is_matched`, and `delivery_queue.status` caused slow query times, especially due to frequent polling by the background worker. Additionally, the worker processed queries for pending deliveries without an upper limit, risking high memory usage. Furthermore, the `match_and_fulfill` method suffered from N+1 query issue since it evaluated a secondary query just to fetch the product related to a given claim.

**Action:** Added `index=True` to the missing boolean columns. Applied a `.limit(100)` to the worker pending delivery query, to restrict memory load and bound execution times per iteration. Used `.joinedload` within `main.py` so that eager fetching prevents querying for the related product later in the process.## 2024-06-04 - Optimize N+1 Query in Worker
**Learning:** Found an N+1 query vulnerability in `worker.py` while fetching related claims for pending delivery queue items. Processing 100 queue items resulted in 100 individual claim queries, adding substantial database roundtrip overhead.
**Action:** Replaced the iterative fetching with an initial batched `IN` query. Gathered all `claim_id` values from the current queue page and queried for claims all at once, loading them into a mapping dictionary to be accessed in O(1) time during iteration. Measured improvement dropping the process time from ~0.05s to ~0.004s. Will look out for similar query loops in background jobs in the future.
